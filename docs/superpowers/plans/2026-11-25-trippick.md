# TripPick 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 여행 기간 사진을 기기 안에서 분석해 흔들림·노출 문제를 표시하고 비슷한 사진·스크린샷을 묶어, 사용자가 고른 것만 앨범에 담고 나머지를 확인 후 지우는 iOS 앱(임시 이름 TripPick)을 만든다.

**Architecture:** 판단 로직(분류, 묶기, 추천, 결정 상태, 요약, 분석, 저장)은 로컬 Swift 패키지 `TripPickCore`에 두고 macOS에서 `swift test`로 빠르게 테스트한다. 앱 타깃 `TripPick`은 SwiftUI 화면만 담당하고 `TripPickCore`의 `TripSession`을 사용한다. 사진 보관함 접근은 `PhotoLibrary` 프로토콜 뒤에 두어 테스트에서는 가짜 구현을 쓴다.

**Tech Stack:** Swift 6, SwiftUI(리퀴드 글래스), PhotoKit, Vision, Core Image, SwiftData, Swift Testing, String Catalog. 외부 라이브러리 없음.

**Spec:** `docs/superpowers/specs/2026-11-25-travel-photo-picker-design.md`

## Global Constraints

- 최소 배포 버전 iOS 26.0, iPhone 전용(`TARGETED_DEVICE_FAMILY = 1`). 패키지 플랫폼은 `.iOS(.v26), .macOS(.v26)`.
- 개발 도구: Xcode 27.2, Swift 6 언어 모드. 외부 의존성과 네트워크 통신 없음(사진 보관함의 iCloud 다운로드 허용 `isNetworkAccessAllowed = true`만 예외).
- 번들 ID `com.trippick.app`(임시), 표시 이름 "TripPick"(임시).
- 모든 화면 문자열은 String Catalog(`Localizable.xcstrings`)에 넣고 en(원본), ko, ja 번역을 같은 커밋에 채운다. 권한 문구는 `InfoPlist.xcstrings`.
- 설정 기본값: 추천 사진 자동 선택 켜짐, 짧은 동영상 기준 2초(1~10초), 화면 모드 시스템.
- 사진 상태는 `keep`(베스트 앨범) / `deleteCandidate`(마지막 확인 후 삭제) / `untouched`(변화 없음) 세 가지. 저장된 결정이 없으면 즐겨찾기는 `keep`, 나머지는 `untouched`.
- 사용자가 직접 정하지 않은 사진은 절대 `deleteCandidate`가 되지 않는다. 삭제는 결과 요약 화면의 버튼과 iOS 시스템 확인 창을 거쳐서만 일어난다.
- 앨범 이름: 사진은 "[여행 이름] Best/베스트/ベスト", 스크린샷은 "[여행 이름] Screenshots/스크린샷/スクリーンショット". 같은 이름이 있으면 그 앨범에 추가한다.
- 짧은 동영상 기준보다 긴 동영상은 어디에도 나오지 않는다. Live Photo는 사진으로 취급한다.
- 리퀴드 글래스: 시스템 컴포넌트(NavigationStack, 툴바, 시트, 버튼)를 기본값으로 쓰고, 사진 위에 뜨는 컨트롤은 `.glassEffect()` / `.buttonStyle(.glass)` / `.buttonStyle(.glassProminent)`을 쓴다. 다크·라이트 모두에서 확인한다.

### Task 3: 비슷한 사진·스크린샷 묶기

**Files:**
- Create: `Sources/TripPickCore/Grouping/{SimilarityGrouper,GroupingThresholds}.swift`
- Test: `Tests/TripPickCoreTests/SimilarityGrouperTests.swift`

**Interfaces:**
- Consumes: `MediaItem`
- Produces:
  - `public struct GroupingThresholds: Sendable { photoMaxGap: TimeInterval = 90; photoMaxFeatureDistance: Float = 0.5; photoMaxMeters: Double = 100; screenshotMaxGap: TimeInterval = 900; screenshotMaxFeatureDistance: Float = 0.6; static let `default` }`
  - `public enum SimilarityGrouper { static func groups(for items: [MediaItem], distance: (String, String) -> Float?, thresholds: GroupingThresholds = .default) -> [[String]] }` — 2장 이상인 묶음만, 각 묶음은 촬영 순서, 묶음끼리도 첫 사진 촬영 순서

알고리즘(시그니처로 정해지지 않으므로 명시): `photo`와 `screenshot`을 따로 처리하고, 동영상은 무시한다. 종류마다 촬영 순서로 정렬하고, 이웃한 두 항목 a(앞), b(뒤)를 아래 조건으로 같은 묶음에 넣는다.
- 사진: `a.burstID != nil && a.burstID == b.burstID`이면 같은 묶음. 아니면 간격 ≤ `photoMaxGap` **그리고** (두 위치 중 하나라도 없거나 거리 ≤ `photoMaxMeters`) **그리고** `distance(a,b)`가 있고 ≤ `photoMaxFeatureDistance`일 때 같은 묶음.
- 스크린샷: 간격 ≤ `screenshotMaxGap` **그리고** `distance` ≤ `screenshotMaxFeatureDistance`일 때 같은 묶음.
- `distance`가 nil(분석 실패)이면 연사가 아닌 한 묶지 않는다.

### Task 5: 추천 사진 고르기

**Files:**
- Create: `Sources/TripPickCore/Recommendation/Recommender.swift`
- Test: `Tests/TripPickCoreTests/RecommenderTests.swift`

**Interfaces:**

점수(명시): 사진 = `0.5 * (aesthetics + 1) / 2 + 0.5 * min(sharpness / 500, 1)`에서 `blurry`·`eyesClosed`는 각각 0.3, `dark`·`overexposed`는 각각 0.15를 뺀다. 스크린샷 = `sharpness`. `failed`인 항목은 제외한다. 동점이면 묶음 안에서 앞선 사진. 모두 실패면 nil.
