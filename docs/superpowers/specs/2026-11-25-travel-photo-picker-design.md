# 여행 사진 고르기 앱 — 설계 문서

작성일: 2026-11-25
상태: 초안 (사용자 승인 전)

## 1. 무엇을, 왜 만드는가

여행지에서는 한 장면을 여러 번 찍는다. 다녀오면 사진이 몇천 장씩 쌓이고, 그중 잘 나온 것만 골라 남기는 일이 너무 힘들다. 이 앱은 여행 기간의 사진을 미리 분석해서 **흔들리거나 어두운 사진을 표시하고, 같은 곳에서 연달아 찍은 사진을 묶어 주어**, 사용자가 "고르기만" 하면 되게 만든다. 고른 사진은 앨범에 담고, 나머지는 사용자가 마지막에 확인한 뒤 지워서 저장 공간을 비운다.

목표는 오늘 개발을 시작해 **가능한 한 빨리 App Store에 무료로 출시**하는 것이다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것

**목표**
- 몇천 장짜리 여행 사진을, 사진 앱에서 한 장씩 넘길 때보다 훨씬 빨리 정리할 수 있다.
- 결과로 "베스트" 앨범이 생기고, 원하면 나머지를 지워 용량을 비운다.
- 애플 기본 앱처럼 보이고 동작한다 (리퀴드 글래스, 다크/라이트 모드).
- 한국어, 영어, 일본어 지원.

**하지 않을 것 (첫 출시 범위 밖)**
- 서버, 로그인, 계정, 클라우드 동기화
- 결제·광고 (완전 무료 출시. 기능 잠금 결제는 추후 업데이트 후보)
- 위치로 여행 자동 찾기 (추후 업데이트 후보)
- 사진 편집, 필터, 공유 기능
- 안드로이드, iPad 전용 화면 (iPad에서는 iPhone 앱으로 돌아가도 됨)

**실패로 보는 것 (작동하더라도)**
- 사용자가 마지막에 명시적으로 확인하지 않았는데 사진이 지워진다.
- 사진이나 분석 결과가 휴대폰 밖으로 나간다.
- 정리하다 앱을 닫았을 때 그동안 고른 것이 사라진다.
- 사진 앱에서 직접 고르는 것보다 느리거나 번거롭다.

## 3. 제약

- 최소 지원: **iOS 26** (리퀴드 글래스와 최신 Vision 분석 기능을 그대로 쓰기 위해). iPhone 대상.
- 개발 환경: Xcode 27.2 (이 Mac에 설치됨), Swift / SwiftUI.
- 모든 분석은 **기기 안에서만** 수행. 네트워크 통신 없음.
- App Store 출시에는 Apple Developer Program 가입(연 $99)이 필요하다.
- App Store 심사에 **개인정보처리방침 URL**이 필요하다. 수집하는 데이터가 없다는 내용의 간단한 웹 페이지면 된다.
- iCloud 사진 보관함을 쓰는 사용자는 원본이 기기에 없을 수 있다. 분석은 기기에 있는 미리보기 이미지로 하고, 필요하면 iCloud에서 받아오게 허용한다(네트워크는 애플 사진 시스템이 처리하며, 앱이 직접 외부로 보내는 것은 없음).

## 4. 만드는 방식 (검토한 선택지)

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. SwiftUI, iOS 26 이상 (선택)** | 진짜 리퀴드 글래스, 애플 사진 분석 기능 전부 사용, 화면 한 벌 | iOS 26 미만 기기는 설치 불가 |
| B. SwiftUI, iOS 18 이상 | 설치 가능한 기기가 조금 더 많음 | 옛 버전용 디자인을 따로 만들어야 해서 출시가 늦어짐 |
| C. Flutter 등 크로스플랫폼 | 안드로이드도 가능 | 리퀴드 글래스를 흉내만 냄, 사진 보관함·분석 연동이 어려움 |

사용자가 **A**를 선택했다. "애플 앱 같은 느낌"과 "빠른 출시" 두 목표에 모두 맞기 때문이다.

## 5. 사용자가 정한 것

- **남은 사진 처리 (C안):** 고른 사진은 앨범에 담고, 나머지는 마지막에 지울지 한 번 더 묻는다. 지운 사진은 iPhone의 "최근 삭제된 항목"에 30일간 남는다.
- **추천 사진 자동 선택:** 설정에서 켜고 끌 수 있다.
  - 켜짐: 묶음마다 앱이 가장 잘 나온 사진을 추천하고 미리 선택해 둔다.
  - 꺼짐: 흔들림 표시와 묶기만 하고 고르는 건 사용자가 한다.
- **짧은 동영상 걸러 내기:** 설정한 시간 이하의 동영상만 따로 모아 보여 준다. 사진처럼 남길 것만 고르고 나머지는 마지막에 지울지 묻는다.
- **무료 출시.**
- **첫 출시에 들어갈 기능:**
  1. 이어서 정리하기 (중간에 앱을 닫아도 하던 곳부터 계속)
  2. 어두운 사진·노출 실패(하얗게 날아간) 사진 표시
  3. 묶음 안 두 장을 확대해서 나란히 비교
  4. 정리 결과 요약 ("1,284장 → 212장, 3.8GB 확보")
  5. 한 장씩 스와이프로 고르기
- **디자인:** 애플 기본 앱 스타일, 리퀴드 글래스.
- **다크/라이트 모드:** 지원.
- **언어:** 한국어, 영어, 일본어.
- **화면 흐름:** 아래 6장의 다섯 화면에 동의함.

## 6. 화면과 동작

### 6.1 여행 고르기
- 시작일과 종료일을 고른다. 해당 기간의 사진 수와 동영상 수, 미리보기 썸네일을 보여 준다.
- "정리 시작"을 누르면 분석이 시작되고 진행률을 보여 준다.
- 처음 실행할 때 사진 보관함 접근 권한을 요청한다. 권한 요청 전에 "사진은 기기 밖으로 나가지 않습니다"를 설명하는 화면을 먼저 보여 준다.

### 6.2 정리 홈
- 여행 이름(기본값: 날짜 범위)과 전체 진행률.
- 분류별 목록과 개수:
  - **비슷한 사진 묶음**
  - **흔들림·어두움** (문제가 있는 사진)
  - **N초 이하 동영상**
  - **스크린샷 묶음** (영상을 보다가 연달아 찍은 스크린샷처럼 비슷한 스크린샷끼리 묶음, 6.9 참조)
  - **한 장짜리 사진** (비슷한 사진이 없는 사진)
- "이어서 정리하기" 버튼은 아직 정하지 않은 다음 항목으로 바로 이동한다.
- "스와이프로 고르기" 버튼은 스와이프 화면을 연다.
- 정리한 여행 목록을 보관해서 다른 여행도 따로 정리할 수 있다.

### 6.3 묶음에서 고르기
- 위쪽에 큰 사진, 아래쪽에 묶음 안 사진 썸네일.
- 표시: "추천"(별), "흔들림", "어두움", "노출 과다", "눈 감음".
- 한 묶음에서 여러 장을 남길 수 있다. 추천이 켜져 있으면 추천 사진이 미리 선택돼 있다.
- 두 장을 골라 나란히 놓고, 함께 확대·이동하며 비교할 수 있다.
- "N장 남기고 다음"을 누르면 나머지는 "지울 후보"가 되고 다음 묶음으로 넘어간다.

### 6.4 스와이프로 고르기
- 한 장씩 카드로 보여 준다. 오른쪽으로 넘기면 "남기기", 왼쪽으로 넘기면 "지울 후보".
- 지울 후보로 넘겨도 실제로 지우지는 않는다.
- 되돌리기 버튼.
- 사진에 붙은 표시(흔들림 등)를 카드 위에 보여 준다.
- (빌더 판단) 대상은 해당 여행에서 **아직 정하지 않은 사진 전체**이며, 촬영 순서대로 나온다. 묶음 화면과 **같은 결정 저장소**를 쓴다. 묶음에 속한 사진을 스와이프로 정하면 그 묶음에서도 정해진 것으로 보이고, 묶음 안 사진이 모두 정해지면 그 묶음은 끝난 것으로 센다. 추천으로 미리 선택된 사진도 스와이프로 바꿀 수 있다.

### 6.5 결과 요약
- "전체 N장 → 베스트 M장", 지울 후보 수, 그대로 둠 수, 비울 수 있는 용량.
- "앨범만 만들기": "[여행 이름] 베스트" 앨범을 만들고 끝낸다. 앨범에는 "남기기"로 고른 것만 들어간다(6.7).
- "앨범 만들고 K장 지우기": 앨범을 만든 뒤 지울 후보를 삭제한다. iOS가 시스템 확인 창을 띄운다.
- 지운 사진은 30일간 "최근 삭제된 항목"에서 되살릴 수 있다는 안내.

### 6.6 설정
- 추천 사진 자동 선택: 켜기/끄기 (기본값 켜짐)
- 짧은 동영상 기준: 1~10초 (기본값 2초)
- 화면 모드: 시스템 / 라이트 / 다크 (기본값 시스템)
- 언어는 iPhone 설정을 따른다 (iOS의 앱별 언어 설정으로 바꿀 수 있음)
- 개인정보처리방침 링크, 버전 정보

### 6.7 결정 상태와 기본값 (사용자 결정)
사진(과 짧은 동영상)마다 상태는 세 가지다.

| 상태 | 앨범 | 지우기 |
|---|---|---|
| **남기기** | 베스트 앨범에 들어감 | 안 지움 |
| **지울 후보** | 안 들어감 | 마지막 확인 후 지움 |
| **그대로 둠** (정하지 않음) | 안 들어감 | 안 지움 |

- 베스트 앨범에는 사용자가 **직접 "남기기"로 고른 것만** 들어간다. 추천을 그대로 두고 다음으로 넘어간 경우도 직접 고른 것으로 본다.
- 처음 상태는 모두 "그대로 둠"이다. 예외는 두 가지다.
  - 추천이 켜져 있으면 묶음의 추천 사진이 "남기기"로 미리 선택된다. 다만 사용자가 그 묶음을 열어 "다음"을 누르기 전까지는 확정되지 않는다.
  - 즐겨찾기 사진은 "남기기"가 기본값이다(6.8 참조).
- 결과 요약은 세 숫자를 모두 보여 준다. 예: "베스트 212 · 지울 후보 900 · 그대로 둠 172".
- 사용자가 보지 않은 사진은 절대 지우지 않는다.

### 6.8 보호와 예외 규칙 (빌더 판단, 사용자 확인 대상)
- **긴 동영상:** 짧은 동영상 기준보다 긴 동영상은 이 앱에서 다루지 않는다. 화면에 나오지 않고, 지울 후보가 되지 않고, 앨범에도 들어가지 않는다. 여행 고르기 화면의 개수에는 "다루는 동영상"(짧은 동영상)만 센다. 기준 시간을 바꾸면 다음에 정리 홈을 열 때 다시 분류한다. 이미 정한 동영상의 결정은 유지한다.
- **즐겨찾기 사진 보호:** 사진 앱에서 하트를 누른 사진은 기본값이 "남기기"이며, 지울 후보로 만들려면 사용자가 직접 바꿔야 한다. 하트 표시를 함께 보여 준다.
- **지우기 영향 안내:** 사진을 지우면 다른 앨범과 공유 앨범에서도 사라진다는 점을 결과 요약 화면에 안내한다.
- **결정은 사진 단위:** 한 사진의 결정은 여행이 아니라 사진에 붙는다. 날짜가 겹치는 두 여행을 만들면, 한쪽에서 정한 사진은 다른 쪽에서도 정해진 상태로 보인다.
- **여행 다시 열기:** "앨범만 만들기" 뒤에도 여행은 목록에 남고, 나중에 다시 열어 고르기를 고치거나 지우기를 할 수 있다.
- **앨범이 이미 있을 때:** 같은 이름의 앨범이 있으면 새로 만들지 않고 그 앨범에 추가한다. 이번 정리에서 지울 후보로 바뀐 사진은 그 앨범에서 뺀다.

### 6.9 스크린샷 (사용자 요청)
요즘은 동영상을 보다가 장면을 스크린샷으로 여러 장 찍는 사람이 많다. 그래서 여행 기간의 스크린샷도 다루고, 비슷한 것끼리 묶는다.
- 스크린샷은 카메라 사진과 섞지 않고 **"스크린샷 묶음"이라는 별도 분류**로 보여 준다.
- 비슷한 스크린샷(같은 영상의 이어진 장면, 같은 화면을 여러 번 찍은 것)끼리 묶는다. 카메라 사진과 달리 위치 정보가 없으므로, 화면 내용의 유사도를 중심으로 묶고 찍은 시각이 가까운지를 보조 기준으로 쓴다(빌더 판단).
- 묶음 화면, 스와이프, 나란히 비교는 사진과 똑같이 쓴다. 흔들림·눈 감음 표시는 스크린샷에는 붙이지 않는다.
- 추천이 켜져 있으면 묶음에서 가장 선명한 한 장을 추천한다(영상 전환 중에 찍혀 뭉개진 장면을 피하기 위해).
- (빌더 판단, 사용자 확인 대상) "남기기"로 고른 스크린샷은 여행 베스트 앨범에 섞지 않고 **"[여행 이름] 스크린샷" 앨범**에 따로 담는다. 결과 요약에도 스크린샷 수를 따로 보여 준다.
- 비슷한 것이 없는 한 장짜리 스크린샷은 "그대로 둠"으로 두고, 스와이프로 고를 수 있다.

## 7. 첫 출시를 위해 필요한 것 (출시 체크리스트)

- Apple Developer Program 가입
- 앱 이름, 앱 아이콘
- App Store 소개 문구와 스크린샷 (한국어, 영어, 일본어)
- 개인정보처리방침 URL과 지원 URL
- App Store 개인정보 항목: "수집하는 데이터 없음"
- 사진 보관함 권한 설명 문구 (세 언어)
- TestFlight로 실제 iPhone에서 테스트한 뒤 심사 제출

## 8. 빌더에게 맡기는 것

다음은 위의 목표와 제약 안에서 빌더가 정한다.

- 흔들림·노출 판별 방식과 기준값 (예: 축소 이미지의 선명도 측정, 밝기 분포)
- 비슷한 사진 묶기 방식 (예: 촬영 시각 간격 + 위치 + Vision의 이미지 특징 비교, 연사 묶음 활용)
- 추천 점수 계산 방식 (예: Vision의 사진 점수, 선명도, 얼굴 품질, 눈 감음 감점)
- 저장 방식 (예: SwiftData)과 분석 결과 캐시
- 비울 용량 계산 방법. 정확한 값을 얻기 어려우면 추정치로 표시
- Live Photo는 사진으로 취급. 스크린샷 판별은 사진 보관함의 스크린샷 표시를 사용
- 스크린샷 유사도 기준값
- 분석 속도 목표와 백그라운드 처리 범위
- 리퀴드 글래스를 직접 적용할 위치 (사진 위에 뜨는 버튼, 하단 바 등)
- 개발 언어 기본값과 문자열 관리 방식 (String Catalog)

## 9. 이번 계획의 범위

- **Apple Developer Program은 나중에 가입한다(사용자 결정).** 이번 계획은 앱을 완성해서 시뮬레이터와 사용자 본인 iPhone에서 돌려 보는 데까지다. 무료 Apple ID로도 본인 iPhone에 설치할 수 있지만, 7일마다 다시 설치해야 한다.
